# جسر إلى الصين — منصة تعلّم اللغة الصينية

منصة عربية لتعلّم الصينية من الصفر حتى **HSK 3**، بمسار متدرّج لا بقائمة أقسام:
الطالب يفتح المنصة فيجد وحدة واحدة مفتوحة أمامه، ويمارس فيها كل المهارات معاً —
يقرأ، ويكتب الحرف بترتيب ضرباته، وينطق فيُقيَّم نطقه، ويحاور، ويقرأ قصة.

منتج تعليمي تابع لشركة **«جسر إلى الصين»** للاستشارات الدراسية والقبول الجامعي.

## المحتوى

| المستوى | مفردات | دروس | وحدات | قواعد |
|---|---:|---:|---:|---:|
| HSK 1 | ٤٠٥ | ١٥ | ٦٩ | ٢٦ |
| HSK 2 | ١٩٥ | ١٥ | ٣٤ | ١٥ |
| HSK 3 | ٤٧٩ | ١٨ | ٨٨ | ٦٢ |
| **الإجمالي** | **١٬٠٧٩** | **٤٨** | **١٩١** | **١٠٣** |

كل كلمة تحمل جملة مثال وتعبير حفظ وجذور الحرف وعدد ضرباته ونبراته.
المحتوى ملفات TypeScript في المستودع، لا في قاعدة البيانات.

## البنية

```
src/
  app/[locale]/      مسارات ar و en — لغة الواجهة تأتي من الرابط لا من المتصفح
  features/          أقسام الواجهة، مستخرجة من الصفحة الواحدة القديمة
  lib/curriculum/    تقسيم الوحدات ومحرك توليد الأنشطة
  lib/entitlement/   صلاحيات الوصول — تُحسم على الخادم
  lib/supabase/      الحسابات وقاعدة البيانات
  data/              المحتوى: مفردات وقواعد ودروس ووحدات مولّدة
supabase/migrations/ الجداول وسياسات الصفوف
design/              مصادر لوحة تصميم الواجهات
scripts/             أدوات البيانات والمدقّق الآلي
```

**الوحدة** هي جلسة المذاكرة: ٥–٨ كلمات، و١٢–٢٠ نشاطاً تدور بين المهارات،
في نحو ست دقائق. لا تُفتح وحدة إلا بإنهاء سابقتها.

**الأقسام الحرّة** (المفردات، الحروف، القصص، المحادثات، الامتحان…) تبقى متاحة
للمراجعة، لكنها **اختيارية خارج المسار الإلزامي**.

## قاعدة البيانات

القاعدة تحمل المستخدمين وتقدّمهم فقط. الجداول: `profiles`, `subscriptions`,
`redemption_codes`, `unit_progress`, `word_progress`, `daily_activity`,
`events`, `app_config` — كلها بسياسات صفوف (RLS).

`unit_progress` مفتاحه `(user_id, level, lesson_no, unit_no)` لأن أرقام الدروس
تتكرر بين المستويات، و`word_progress` يحمل `level` صريحاً لا مستنتَجاً من نطاق
المعرّف.

**السعر لا يُكتب في الكود.** يعيش في `app_config` ويُحرَّر من لوحة التحكم.

## الهوية البصرية

| اللون | Hex | الدور |
|---|---|---|
| الأزرق الموثوق | `#1B3A6B` | **لون الإجراء** والأسطح الأساسية |
| الأحمر الصيني | `#C8102E` | الخطأ والتمييز |
| الذهبي الإمبراطوري | `#D4AF37` | الإنجاز والتميّز |
| العاجي | `#F7F4EF` | الخلفية الفاتحة |
| الفحمي | `#2A2A2A` | نص المتن |

الخطوط: **Cairo** للعناوين، **Tajawal** للنصوص، **Noto Sans SC** للصينية.

ثلاث قواعد مشتقة من قياس التباين لا من الذوق:

- الأحمر على الكحلي يعطي **1.91** — فالوضع الداكن يستعمل `#E23A4E` (4.27).
- الذهبي نصاً على العاجي يعطي **1.92** — فهو شكل وفاصل على الفاتح، ونص على الداكن فقط (8.62).
- الكحلي هو زر الإجراء لا الأحمر، لأن الأحمر يعني «إجابة خاطئة» داخل التمارين،
  والحكم لا يعتمد على اللون وحده أبداً — أيقونة وحدّ وشرح معه.

المكوّنات تقرأ رموزاً دلالية (`--clr-*`, `--text-*`, `--surface-*`) لا ألواناً صريحة.

## التشغيل

```bash
npm install
npm run dev          # http://localhost:3000
```

المنصة تعمل **بلا أي إعداد**: بلا حساب، وبلا قاعدة بيانات، وبلا بوابة دفع.
التقدّم يُحفظ في المتصفح، وكل درس ووحدة يشتغل. ما يعطّله غياب الإعداد هو
مزامنة التقدّم بين الأجهزة، والاشتراكات، ولوحة التحكم — لا التعلّم نفسه.

### بوابات الجودة

```bash
npm run check              # الستّة معاً — يجب أن تمرّ قبل أي إيداع
npm run build              # ثم:
node scripts/check-paywall.js
```

| البوابة | ما تمنعه |
|---|---|
| `typecheck` | — |
| `validate:content` | نطاقات المعرّفات، تكرار الكلمات، لغة كل حقل، وحدانية ربط الكلمة بدرسها، تطابق النبرات، مراجع خريطة الطريق |
| `check:activities` | وحدة تبني تياراً معطوباً: سؤال بلا إجابة صحيحة، خيارات مكرّرة، كلمة تُطلَب قبل أن تُقدَّم، نوع يتكرّر أكثر من ثلاث مرات، تيار غير حتمي |
| `check:progress` | مسار لا يُفتح خطوةً خطوة، مستوى لا يصل ١٠٠٪، إنجاز لا يمكن ربحه، عدّاد الهدف اليومي لا يتحرّك |
| `check:payments` | رقم سعر أو مفتاح مزوّد في `src/`، دفعٌ ينفتح نصفه، متغيّر بيئة غير موثّق |
| `check:admin` | لوحة بلا حارس على الخادم، مسار إداري بلا تفويض، دالة SQL غير مقيّدة |
| `check-paywall` | مفردة مدفوعة في صفحة أو **في حزمة جافاسكربت عامّة** — تحتاج `npm run build` قبلها |

`check-paywall` يفحص الحزم لا الصفحات وحدها، لأن أول نسخة منه فحصت HTML فقط
فمرّت خضراء بينما كل مفردات HSK2 وHSK3 تُوزَّع في ملف `.js` واحد.

## التشغيل الحقيقي

المنصة تعمل بلا هذا كلّه؛ وهذا ما يُشغّل الحسابات والبيع. الخطوات بالترتيب،
وكلٌّ منها مستقلّ — تقف عند أيّها شئت.

### ١. قاعدة البيانات والحسابات

```bash
cp .env.example .env.local     # ثم املأ متغيّرات Supabase الثلاثة
```

من [supabase.com](https://supabase.com): مشروع جديد ← Settings → API. أول
متغيّرين عامّان بالتصميم، والثالث (`SERVICE_ROLE`) خادميّ ولا يُعرَض أبداً —
الكود يرمي استثناءً إن قُرئ في المتصفح.

طبّق الترحيلات العشرة في `supabase/migrations/` بالترتيب، من محرّر SQL أو
عبر `supabase db push`.

**الدخول بجوجل:** من Supabase → Authentication → Providers → Google، وأضف
`https://<نطاقك>/auth/callback` في Google Cloud Console. الرابط بلا مقطع لغة
عمداً — هو مسجّل عند جوجل فلا يجوز أن يتحرّك.

### ٢. أول مدير

```bash
ADMIN_BOOTSTRAP_EMAILS=your@email.com
```

سجّل الدخول بذلك البريد، ثم `POST /api/admin/bootstrap` مرّة واحدة. **امسح
المتغيّر بعدها**: الإدارة صارت قيمة في `profiles.role`، وإبقاء القائمة يعني أن
من ظهر فيها يوماً يحتفظ بالمفاتيح.

ثم `/ar/admin` — ومن هناك يُضبط السعر ويُولَّد أول كود.

### ٣. البيع بالأكواد — بلا بوابة

أسرع طريق إلى أول ريال: لوحة التحكم ← الأكواد ← دفعة. لا تحتاج بوابة ولا
مراجعة تاجر ولا انتظاراً. وهي نفسها ترتيب المؤثّرين: دفعة باسم، مُتتبَّعة،
تُلغى كاملةً إن انتهى الاتفاق.

### ٤. بوابة الدفع — حين تجهز

لا بوابة تقبل بائعاً يمنياً. والحساب المصري يفتح Paddle أو Lemon Squeezy،
وكلاهما **تاجر مسجَّل** يجمع الضريبة في بلد المشتري ويحوّل إلى حساب واحد —
وهو ما يجعل البيع إلى اليمن ومصر والصين وروسيا من متجر واحد ممكناً أصلاً.

الاثنان منفَّذان خلف عقد واحد. أيّهما قبِلك: املأ مفاتيحه في `.env.local`،
ثم اختره من لوحة التحكم. **بشرطين معاً** — أن تختاره وأن تكون مفاتيحه حاضرة؛
اختيارُ بوابة بلا مفاتيح يُبقي الدفع مغلقاً بدل أن ينتج زرّاً يعطي خطأ.

سجّل عنوان الـwebhook عند المزوّد: `https://<نطاقك>/api/webhook/lemonsqueezy`
أو `/api/webhook/paddle`.

### ٥. المعلّم الذكي (اختياري)

`ANTHROPIC_API_KEY`. بدونه يبقى المعلّم على محرك القواعد ويجيب المتكرر بلا
تكلفة. مع المفتاح يتولّى النموذج ما عجزت عنه القواعد — للمشتركين وبحدّ يومي
يُضبط من اللوحة، فالتكلفة مربوطة بالإيراد.
